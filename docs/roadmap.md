# Project Arena roadmap

The roadmap is ordered by business proof, not feature volume.

## Phase 0 — Founding Arena readiness

**Outcome:** one trustworthy, operator-controlled rehearsal of the complete
Arena loop.

- Baseline and migrate production safely.
- Prove magic-link auth on the canonical domain.
- Complete sandbox checkout, signed webhook, approval, scoring, finalization,
  email, and refund tests.
- Configure live Stripe and run one low-value live payment/refund.
- Configure transactional email with replies delivered to
  `hello@projectarena.xyz`.
- Promote only a verified preview and record launch metrics.

Exit gate: every P0 item in `founding-arena-launch-readiness.md` is green.

## Phase 1 — Founding Arena

**Outcome:** at least one external Builder pays, competes, receives measurable
qualified traffic, sees a permanent result, and understands the value.

- Run one open-category, 16-Project, 48-hour Arena.
- Manually review every Project and fraud flag.
- Give every Builder a performance report: qualified visits, Supporters,
  impressions, visit rate, final rank, and Arena Rating change.
- Publish Champion and result share cards.
- Interview every paying Builder within 48 hours of the close.

Exit gate: real paid Entry, reliable close, no unresolved payment/security
incident, and evidence that at least one Builder would enter again.

## Phase 2 — Repeatability

**Outcome:** prove this is a repeatable distribution product, not a single
event.

- Schedule the next Arena before the current one ends.
- Add a repeat-entry CTA and one-click Project reuse.
- Automate lifecycle emails and operational alerts.
- Build funnel reporting from Arena view -> entry start -> Checkout -> paid ->
  approved -> competing -> next Arena.
- Define cancellation, rejection, refund, tie, correction, and incident policy.

Exit gate: three completed Arenas, at least 30% repeat entry among eligible
Builders, and a stable operator workload.

## Phase 3 — Distribution quality

**Outcome:** improve the value of attention delivered to Projects.

- Add category Arenas only when applicant supply supports them.
- Improve Qualified Visit rules and fraud evidence without rewriting historical
  results.
- Add Builder acquisition attribution and share conversion.
- Publish Arena quality metrics and transparent scoring explanations.
- Test sponsorship as clearly labeled exposure that does not affect rank.

Exit gate: Builders can connect entry spend to credible visits and discovery,
and Supporters return without being recruited by a competing Project.

## Phase 4 — Scale the format

**Outcome:** expand formats after the core loop is economically and
operationally sound.

- Premium themed Arenas and partner-operated Arenas.
- Team workflow and delegated Project management.
- Public API and embeds for live standings and results.
- Arena Rating-based invitations and seasonal championships.

`$PRENA`, subscriptions, Battles, and speculative reward mechanics remain
outside the launch path until Phase 2 is proven. They must strengthen earned
competition, never turn payment into rank.
